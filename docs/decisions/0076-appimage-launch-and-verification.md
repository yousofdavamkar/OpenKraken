# 0076 — AppImage launch and verification

M8 requires AppImage packaging alongside DEB/RPM. The inspected electron-builder launcher can automatically add `--no-sandbox` when user namespaces are unavailable. That behavior conflicts with the application's renderer sandbox requirement.

Build an AppDir around a byte-for-byte copy of the hardened Linux bundle using [appimagetool 1.9.1](https://github.com/AppImage/appimagetool/releases/tag/1.9.1) and the [type-2 runtime release 20251108](https://github.com/AppImage/type2-runtime/releases/tag/20251108). Pin architecture-specific tool and runtime SHA-256 digests from the official release asset metadata. Verify downloads and cache hits before execution, cap download size, and supply the runtime explicitly so the tool cannot select a moving runtime release. The producer tool is run through its extraction mode, avoiding a build-time FUSE dependency.

The independently written `AppRun` resolves its own directory and directly executes the packaged application, preserving arguments, working directory and exit status. It never injects sandbox-disabling switches or changes the host's user-namespace policy. The desktop file, icon, runtime license notice and explicit unsigned/test release metadata accompany the bundle. AppImage does not install packages or register system-wide launchers. Git 2.38+, system CA certificates, Electron's desktop libraries and the Linux native ABI baseline remain host prerequisites. Normal launch also needs a working FUSE setup. A host that prohibits Chromium's sandbox must be configured by its administrator; the launcher does not weaken isolation automatically.

Record the complete AppDir manifest, including file modes, links and hashes. Compare the application subtree against the source bundle after image production and verify that the source remains unchanged. Verification checks the final archive hash before executing its extraction command, compares the extracted AppDir, checks the reviewed launcher and desktop entry, and reads Electron's hardened fuses. As with DEB/RPM, this accepts only locally built or independently authenticated artifacts: an adjacent unsigned manifest is not an authenticity proof.

Desktop smoke launches the actual AppImage through its runtime, both with normal FUSE mounting and with `APPIMAGE_EXTRACT_AND_RUN=1`. It exercises renderer isolation, native helpers, folder selection, repository opening, Bash integration, keyboard delivery and terminal exit. Launcher tests use literal arguments, empty arguments, paths containing spaces, a misleading `APPDIR`, working-directory preservation and a nonzero exit status. Separate negative checks reject archive and native-helper hash mismatches before desktop launch.

An extraction-mode smoke exposed a test cleanup bug: disconnecting CDP and terminating the supervising runtime left Electron alive. The smoke now obtains the browser PID through CDP, terminates that process, and waits for the runtime to exit. The existing two-second shutdown bound fails if forced cleanup is necessary. Tests and producer invocations isolate runtime temporary files inside their own disposable directories. This pinned runtime left extracted files behind during local testing even after its normal exit, so cleanup does not rely on its removal behavior.

Linux x64 is the runtime acceptance boundary in this checkpoint. Architecture-specific pins support native arm64 builds, but arm64 execution, older distributions, restricted user-namespace environments, signed distribution, update delivery and external beta acceptance remain unverified. Bundled third-party notices do not supply the project's missing release license or complete a distribution compliance review.
