# Commit-bound pull-request checks

The PR Checks section reads GitHub/GHES `statusCheckRollup` through GraphQL. A fixed main-process query selects the PR's current head and last commit, then pages the rollup's check runs and legacy status contexts. Both returned commit IDs must match the head displayed in PR details. A mismatch clears displayed results and requires refreshing details; old successful checks are not relabeled as belonging to a newer head.

The query uses the configured provider's GraphQL endpoint (`api.github.com/graphql` or the configured Enterprise origin's `/api/graphql`). It shares the existing credential authorization, refresh, HTTPS host guard, cookie refusal, redirect refusal, cancellation, 20-second timeout and 4 MiB response cap. Public IPC accepts only a repository, PR number, head commit and bounded cursor; it accepts no queries, URLs or tokens. It is not a Git utility operation.

A normalized page contains the head, provider-computed rollup state, total context count, at most 100 rows and a next cursor. Check runs retain status and nullable conclusion; legacy statuses retain state and nullable description as literal text. A null rollup means no reported results, never success. Null nodes, unknown enum values, missing metadata, oversized fields and GraphQL errors (including partial-data errors) fail with a sanitized error. No raw GraphQL error message is shown. A completed check with no conclusion is labeled as such. This display does not certify that branch rules, required reviews or other merge conditions are satisfied; the existing merge operation still relies on provider enforcement.

The desktop appends and deduplicates rows by provider ID, replacing a repeated row's current state. It renders a virtualized list with keyboard scrolling and explicit Home/End navigation. Ten pages cap the display at 1,000 contexts and an explicit message indicates more results. Repeated cursors stop paging and clear results. A rollup that disappears during paging clears rows from earlier pages. Refresh starts again at the first page, and leaving the section cancels the request. Errors do not leave an apparently current successful rollup. Pages are observations, not a transactionally consistent snapshot: checks may finish, restart or disappear while paging, and provider counts can change. Refresh is manual in this slice; scheduled PR/check polling remains separate work.

MSW coverage exercises the real provider service/vault and HTTP boundary for GitHub and Enterprise: mixed check types, cursor parameters, null rollups, mismatched heads, malformed/partial GraphQL data, unknown states, field/page bounds, repeated cursors, cancellation, redirects, denied access and response size refusal. Strict IPC tests reject query/URL/token injection and missing head identities. Electron coverage keeps real main/preload/UI routing and verifies retry, literal text, append/deduplication, state refresh, disappearing rollups, cursor cycles, stale-head clearing, detail refresh, 1,000-row limits with bounded DOM rows, keyboard reachability and cancellation when leaving Checks. Provider responses and OS encryption are fixture boundaries; live-provider and real-keychain acceptance remain unverified.

Public schema references: [GitHub commit rollups](https://docs.github.com/en/graphql/reference/commits#statuscheckrollup), [check-run fields and states](https://docs.github.com/en/graphql/reference/checks#checkrun), and [pull-request commit connection](https://docs.github.com/en/graphql/reference/pulls#pullrequest).
