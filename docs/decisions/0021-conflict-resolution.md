# Conflict documents and recoverable resolution

Conflict documents come from native unmerged index stages, matched using raw NUL-delimited path bytes. Stage 1 is base, 2 is ours, and 3 is theirs. Missing stages represent additions or deletions. During rebase these are Git's stage meanings: ours is the rebased destination, theirs is the replayed commit.

Text editing is restricted to regular UTF-8 files without NUL, at most 2 MiB per version/output. Binary, oversized and symlink versions remain available as whole-side choices. Native checkout-index applies the selected stage (including working-tree filters), then index-info stages that exact object and mode. This preserves executable bits even when core.filemode is disabled. Edited output uses native add. An absent side or explicit deletion removes the path and its stages. Submodule choices update the gitlink only; they never check out or delete submodule working files.

A review token covers HEAD/index revision, native operation metadata, stages and raw working-file images. Resolution rechecks it under the index lock. Text writes use the validated backup path layer and atomic file replacement. Resolution is journaled with before/after index and working bytes; Undo restores conflict stages and raw contents and refuses newer changes. Raw backup limits apply, and a pending record preserves recovery material after an uncertain failure. These are optimistic checks, not a filesystem-wide editor lock.

The native fixture corpus covers text edits, add/add, delete/modify, binary, rename/modify and submodules. Public Git stages, working files and Undo results are the acceptance seam.

The renderer uses `node-diff3` 3.2.1 in a dedicated Web Worker. Inputs retain their line endings, are bounded to 2 MiB/10,000 lines per side and 2,000 result parts, and a five-second timeout terminates stalled computation. The editor presents ours and theirs above an editable output, with the base available separately. Chunk or per-line selection assembles a candidate output; switching to chunk editing explicitly replaces the current draft. Existing working text is the initial output. A conflict-free computed result can be staged with the explicit Auto-merge action. Worker failure leaves manual output editing available. Reference: [node-diff3](https://github.com/bhousel/node-diff3).


External-tool launch uses Git's configured `merge.guitool` or `merge.tool` through `git mergetool --no-prompt`; the renderer cannot supply a command. Tool settings are included in the review fingerprint. Git owns tool execution, backup preferences and success detection. The operation runs with the private index, permits cancellation from the dialog, and journals partial file changes even when cancelled. The initial integration accepts UTF-8 paths and simple alphanumeric, underscore or hyphen tool names. Submodule pointer conflicts use the native index choices instead of a text merge tool.
