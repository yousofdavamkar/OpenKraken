# 0075 — Linux native build baseline

The Debian 13 install fixture reproduced a compatibility failure hidden by packaged smoke on the build host: `node-pty` linked `cfsetispeed` and `cfsetospeed` at `GLIBC_2.42`, while the fixture provides glibc 2.41. Archive verification confirmed that these were the original host-built bytes. The libraries themselves were installed; their symbol versions were incompatible. A direct `ldd` check of the installed module reproduces the failure in seconds.

Linux packaging now rebuilds the staged `node-pty` package inside a Debian 13 compiler image before creating the hardened Electron bundle. The base image is pinned by its multi-architecture OCI digest. Packaging selects the process architecture explicitly, compiles as the caller's UID/GID with network access disabled, mounts tool dependencies read-only, and grants write access to the staged native package. Docker or Podman is a Linux packaging prerequisite. The compiled package runs directly on the desktop.

Use pinned node-gyp 12.4.0 and the distribution's compiler/Node headers, with `NAPI_VERSION=8`. `node-pty`'s Unix implementation uses Node-API, and [Node's ABI contract](https://nodejs.org/api/n-api.html#node-api-version-matrix) supports modules targeting that API on later runtimes. This contract does not cover glibc or arbitrary V8/libuv APIs; the OS build baseline and packaged runtime checks are still necessary. Electron, React and TypeScript runtime/build pins remain in their existing workspace manifests.

Cache the compiler image by Dockerfile contents and architecture and log its immutable image ID. Package versions within the compiler image come from authenticated Debian repositories at image construction time; this is not a claim of byte-for-byte reproducible builds. Release CI constructs its own image. Compilation occurs in staging, preserving the development dependency installation.

The acceptance boundary is the extracted/installed artifact: reject unresolved ELF libraries or symbol versions in Electron and the native modules, then exercise the packaged native terminal, helpers and renderer isolation. The original module fails and the rebuilt module passes the same Debian library check. The separate install/reinstall/remove fixture checks launch registration and user-data retention. CPU architecture routing is configured for x64/arm64; only Linux x64 runtime evidence is established in this checkpoint. Older distributions, graphical sessions in other distributions and cross-platform runtime certification remain open.
