# 0109 — Zsh shell integration

OpenKraken starts an interactive, non-login zsh with bundled startup wrappers selected by a temporary `ZDOTDIR`. The terminal host saves whether the original variable existed and its literal value after removing inherited OpenKraken control variables. The wrapper restores that value, removes the private environment controls, and sources the user's `.zshenv` at top level. It retains changes made there, including redirecting `ZDOTDIR`, before selecting the bundled `.zshrc`. That wrapper restores the resulting directory setting and sources the user's `.zshrc` at top level before installing integration. No user/repository startup file is created or edited.

This preserves the scope of ordinary `typeset` and option changes, as well as the distinction between an unset directory and an inherited value. Configuration paths are quoted data, not evaluated shell text. Native global startup files still run in zsh's normal order. The global `.zshrc` can observe the temporary wrapper directory; unusual global startup policies that disable or redirect later startup are not covered by this Linux acceptance. Login-shell startup is not introduced.

Integration appends functions to `precmd_functions` and `preexec_functions`; existing named hooks and array entries remain in place. The last prompt hook wraps the current `PROMPT` in nonprinting OSC 133 A/B markers and removes only its previous wrapper. Subsequent prompts include D with zsh's `%?` prompt expansion for the previous command status. The preexec hook emits C. No command text is captured, and prompt substitution is not enabled by the integration. Existing prompt replacement, command status and pipeline status are retained in the tested cases. The first prompt has no invented exit result. Right prompts and user key bindings are untouched.

Integration declines disabled prompt-percent expansion, read-only prompt/hook variables and conflicting integration function names. If the user's `.zshenv` disables RCS or makes `ZDOTDIR` read-only, it leaves the normal startup path in control. A regression caught an attempted write to a read-only directory variable; that configuration now falls back without a shell diagnostic. User hook failures or later replacement/removal of hook arrays continue to follow native zsh behavior; arbitrary prompt plugins and custom global startup policies need further coverage.

The build copies the wrapper directory, including dotfiles, beside the terminal service. Packaged launches resolve it under `app.asar.unpacked`. The packaging smoke supports an explicit Bash/zsh executable and exercises native keyboard input and command status, so missing or incorrectly unpacked startup files fail at runtime. Linux CI installs zsh and runs both the normal terminal tests and a separate packaged zsh smoke.

Acceptance uses native zsh 5.9 from the extracted Ubuntu `5.9-8ubuntu3` package, without modifying the system shell. Electron cases cover normal HOME startup, inherited `ZDOTDIR`, `.zshenv` redirection, exactly-once startup, unchanged user files, named/array hooks, dynamic prompts, failed commands and pipeline status, hiding and native exit. Fallback cases cover read-only prompts, disabled prompt-percent expansion, disabled RCS and a read-only directory. macOS/Windows runtime acceptance, global startup edge cases and PowerShell integration remain open.

References: [zsh startup files](https://zsh.sourceforge.io/Doc/Release/Files.html), [native hook functions](https://zsh.sourceforge.io/Doc/Release/Functions.html), and [ADR 0066](0066-terminal-shell-integration.md).
