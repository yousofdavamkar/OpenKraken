# Repository issue browsing

The desktop Issues panel reuses the saved-account repository picker and calls GitHub/GHES directly through the existing protected provider service. It supports open, closed and all-state lists, details and paged comments. Issue creation, comment submission and issue-state changes remain separate work; this panel currently performs reads only.

GitHub's REST issue-list endpoint includes pull requests. Entries carrying `pull_request` are excluded, while continuation is calculated from the raw response length. Consequently a page containing only PRs can be empty in the UI and still offer Load more. The panel does not claim the repository has no issues until there is no continuation. Lists request 100 entries ordered by creation date descending and stop after 100 provider pages with a display-limit notice. The provider's offset paging is not a stable snapshot; updates can shift entries between pages. Refresh clears the loaded pages, and append deduplicates by issue number, replacing metadata on repeated entries.

Strict issue metadata includes number, title, state/reason, author, timestamps, labels, assignees, milestone, lock state and comment count. Descriptions are loaded only for the selected issue. Display URLs are constructed from the configured HTTPS origin and selected repository, never copied from arbitrary response links. Bodies, labels, names and descriptions render as literal text. Deleted authors and absent milestones/assignees are labeled. Unexpected metadata, oversized pages/text or invalid IDs fail with sanitized errors.

Details must match the requested number and must not be a pull request. Comment reads recheck that issue first and validate each comment's `issue_url` against the selected repository/number on the configured API host. IDs must be safe positive integers before conversion to display strings. Comment pages are ordered by the provider, appended and deduplicated by ID. The desktop caps comments at ten 100-entry pages and labels further results as outside the display limit. Both issues and comments are virtualized; keyboard navigation reaches unmounted list rows and Home/End reaches the first/last loaded comment.

The typed IPC boundary accepts only bounded repository, state, number and page selectors. It rejects arbitrary URLs, credentials and extra arguments; these methods are not accepted by the Git utility. The provider driver retains configured-host checks, encrypted credentials, protected refresh, cookie/redirect refusal, bounded HTTPS responses, timeouts and cancellation. Changing the repository/state/selected issue or closing the panel cancels obsolete requests and suppresses late responses. Retrying a failed page preserves previously loaded rows; explicit refresh starts from page one.

MSW tests cover Enterprise list filtering, PR-only continuation, metadata normalization, canonical URLs, deleted authors, closed issues, literal bodies, issue/comment paging and bounds, malformed metadata, foreign comments, accidental PR selectors, mismatched numbers, cancellation and sanitized provider failures. Electron acceptance keeps the actual main/preload/UI boundary and exercises failure/retry, append/deduplication, search, keyboard selection, bounded mounted rows, literal descriptions/comments, comment refresh and the 1,000-comment cap, state changes and cancellation on repository changes. HTTP and OS encryption remain fixture boundaries. Live provider/keychain and cross-platform acceptance remain open.

Public references: [repository issues and the PR distinction](https://docs.github.com/en/rest/issues/issues#list-repository-issues) and [issue comments](https://docs.github.com/en/rest/issues/comments#list-issue-comments).
