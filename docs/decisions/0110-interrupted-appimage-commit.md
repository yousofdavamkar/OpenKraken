# 0110 — Reopen the installed AppImage after an interrupted commit

Main arms the restart helper after the user accepts shutdown and before atomically renaming the staged AppImage over the installed file. If main dies in that interval, the installed file is still the predecessor. The helper used to exit because that file did not match the signed replacement. A user had to reopen the app manually.

Once the armed helper observes its parent's exit, it checks the installed replacement as usual. If that check fails, it can launch the predecessor in place only when the prepared transaction still matches the plan received from main. The recovery directory must contain exactly the private journal, the private staged replacement and the retained predecessor. The helper checks all three digests, current ownership and permissions, and the sizes of both images. The installed path and retained predecessor must refer to the same inode with exactly two hard links. The helper rechecks file identity and directory state before launch. Uncertain evidence leaves the files available for inspection.

The helper reopens the verified predecessor once with the original profile. Its existing startup recovery discards the interrupted staging and journal. A rollback notice is reserved for a replacement that actually required restoration. If main dies immediately after the rename, the installed image matches the signed replacement and goes through ordinary supervised startup instead. Both paths preserve the stored release sequence.

The packaged Linux test kills the fixture main process on either side of the real rename. It checks the boot sequence, installed digest, retained release sequence, absence of a rollback notice and removal of the transaction. This covers process death while the armed helper survives. Physical power loss, helper death, a hung replacement and incompatible profile migrations remain separate cases. See [startup exit recovery](0086-appimage-startup-exit-recovery.md) and [restart helper preflight](0087-appimage-restart-helper-preflight.md).
