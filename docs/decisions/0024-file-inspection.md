# Native file inspection

Commit file lists use native `diff-tree --raw -r -z --no-abbrev -M` with external diff/textconv disabled. Paths are parsed as independent NUL records and retained as base64 bytes alongside display text; rename records contain both original and destination paths. Modes, native blob IDs and similarity scores stay attached to each change. The first parent is the default comparison, a merge's other native parents can be selected explicitly, and root commits compare against the empty tree through `--root`.

The service validates commit/parent OIDs and refuses a supplied parent that is not one of the commit's native parents. File lists are bounded to 10,000 entries/16 MiB and rename matching to 1,000 candidates; execution uses the repository read queue and cancellation. Native acceptance checks renames with spaces/control characters, additions, modifications, deletion, roots and both merge parents. A seeded streaming-parser property test preserves arbitrary raw path bytes over varied chunk boundaries; malformed/truncated records are refused. Reference: [Git diff-tree](https://git-scm.com/docs/git-diff-tree).

Commit details now request these lists through typed IPC and virtualize the changed-file rows. Merge-parent selection reloads the comparison without changing history or the working tree. Requests are cancelled when the detail view changes or closes. Desktop acceptance selects both parents of a merge and checks the corresponding independent file lists; existing graph keyboard navigation remains covered.

File comparisons read immutable blob IDs from that native change list. Gitlinks are shown as submodule IDs without dereferencing them as blobs. UTF-8 text is compared with native `git diff --no-index` against private temporary files, with external drivers and text conversion disabled; the temporary directory is removed in `finally`. This keeps Git's hunk and whitespace semantics while allowing decoded text to use the same comparison path later. Original modes, paths and object IDs remain separate from the temporary diff headers. Reads and diff processes are cancellable and bounded. Binary content is reported without returning its bytes as text.

The initial text guard is 2 MiB or 10,000 lines. Explicit loading can raise it to 20 MiB or 250,000 lines, which remain hard limits; a byte guard may discover a line guard only after loading. Native service tests verify contents, hunks, whitespace options, binary classification and an explicit 50,000-line load, and check that HEAD and workspace status stay unchanged. Rendering/performance acceptance is separate from these backend tests.

The commit viewer loads on demand so CodeMirror does not enter the initial graph bundle. Hunk rows use TanStack virtualization; inline/split views use read-only CodeMirror 6 merge views. Native hunk ranges override CodeMirror's full-document diff, preserving Git whitespace filtering; optional word highlights refine only changed ranges with a bounded diff budget. JavaScript/TypeScript syntax highlighting is enabled by filename. Closing or changing a comparison cancels its service request. Desktop acceptance covers parent selection, view switching, whitespace filtering, and explicit large-file loading; the 50,000-line fixture opened in 445 ms on the Linux development machine, with bounded DOM rows in all three views. This is a local performance observation, not cross-platform acceptance. Binary and submodule entries display object IDs and metadata. See [CodeMirror merge](https://code.haverbeke.berlin/codemirror/merge) for the public rendering API.

Text decoding first honors an explicit supported encoding, then a UTF-16 BOM or valid UTF-8, then a bounded 64 KiB chardet sample with at least 50% confidence. Unsupported/ambiguous candidates and control or replacement-character output remain binary. Supported legacy encodings use iconv-lite. The viewer exposes an encoding override because detection is a heuristic; this read-only choice never rewrites a blob or workspace file. Native fixtures verify independently encoded Shift-JIS, BOM-marked UTF-16LE and an explicit Windows-1252 override. Working-tree attribute handling belongs to the subsequent WIP editor slice. Public APIs: [chardet](https://github.com/runk/node-chardet), [iconv-lite](https://github.com/pillarjs/iconv-lite).

Image previews accept byte-identified static PNG, JPEG and WebP only. Header dimensions are read with image-size before any image reaches Chromium; each side is limited to 16,384 pixels per dimension and 40 million total pixels, in addition to the blob byte limits. PNG animation chunks and WebP animation flags are refused. Unsupported formats remain text or binary, and SVG/HTML is never placed in an image element. Data URLs use a fixed raster MIME allowlist under the existing CSP. The viewer offers side-by-side images and an opacity overlay, reports dimensions and decoding failures, and does not modify bytes. Native tests cover raster classification, oversized headers and markup disguised by an extension; the desktop test verifies image decoding and overlay control. Header validation does not certify full image integrity; Chromium remains responsible for decoding. References: [image-size](https://codeberg.org/image-size/image-size), [PNG specification](https://www.w3.org/TR/png-3/).

File history uses native `log --follow --name-status -z` pinned to an immutable commit. A native regression demonstrated that `--skip` can skip rename processing and lose older history. Pages therefore replay a bounded prefix and discard earlier parsed entries, preserving rename traversal across page boundaries even if HEAD changes. This trades additional traversal for deterministic pages without a persistent Git process. Pages contain at most 200 entries; the replay offset is capped at 10,000 and output at 32 MiB with the standard cancellation/timeout. Native paths are retained per historical entry, including the old name before a rename. The Node process argument boundary currently requires a UTF-8 starting filename and refuses unsupported raw names explicitly. Literal pathspecs prevent filename metacharacters changing the query. Native tests cover rename paging and a moved HEAD; the NUL parser has seeded arbitrary-byte/chunk-boundary coverage. Reference: [Git log](https://git-scm.com/docs/git-log).

The comparison dialog exposes a virtualized file-history panel. Older pages append to the same list; selecting a revision loads its native change under the path recorded for that revision. Requests cancel on panel closure, and failures offer a retry. The panel distinguishes the bounded display limit from the natural end of history. Desktop acceptance traverses 53 revisions across a page boundary and opens the original filename before a rename.

Blame uses `git blame --line-porcelain --encoding=UTF-8` against the selected immutable commit. A regular UTF-8 blob is checked before attribution; the initial limits are 2 MiB and 50,000 lines. Legacy encodings and binary/link/gitlink entries receive an explicit unsupported result. Metadata and text stream through a bounded line parser in batches of 64, then through request-scoped validated IPC events. The virtualized view batches React updates per animation frame, keeps only visible rows in the DOM, and shows author, commit, original line and summary metadata. Closing it cancels the native process. Native tests check line attribution, cancellation/queue release and binary refusal; seeded parser tests exercise varied UTF-8 boundaries and malformed records. The isolated Linux desktop fixture displayed the first screen of a 10,000-line file in 128 ms and verified the final line with bounded DOM rows. Reference: [Git blame](https://git-scm.com/docs/git-blame).

Rich WIP comparisons distinguish HEAD→index from index→worktree. Staged views read native blob IDs, including the old path of a staged rename. Unstaged views reconstruct canonical Git contents from a complete native `diff --text` patch applied to the exact index blob, preserving arbitrary bytes and final-newline state before decoding. This honors native clean filters and working-tree encoding without staging the file. Untracked paths use an intent-to-add entry in a private temporary index, removed afterward. Patch markers and blank-context formatting are explicitly controlled; context and hunk counts are validated. Large unchanged prefixes are copied iteratively to avoid argument-count limits. Raw worktree images and HEAD/index fingerprints are rechecked before returning. The existing partial-staging API remains independent and retains its review tokens.

Native tests distinguish HEAD/index/worktree contents, exercise a clean filter and untracked files, preserve no-final-newline output and load a 250,000-line prefix. A seeded property test reconstructs arbitrary byte contents from native patches. WIP inspection uses the comparison byte/line caps; initial path arguments require UTF-8, unresolved conflicts use the conflict editor, and submodule worktree comparisons await the submodule controls. The canonical Git representation shown by a diff may differ from the raw encoding preserved by the working-file editor.

The WIP diff dialog links to the same full comparison surface used for commits, including hunk/inline/split, whitespace, encoding and image controls. Returning to line selection requests a fresh exact native diff and review token; filtered display hunks are never treated as staging instructions. The desktop flow verifies HEAD→index and index→worktree contents, switches to split view, returns to selection and stages the reviewed change. Existing partial-staging, discard and watcher acceptance remains green. Additional native cases cover staged rename/deletion and Git's UTF-16 working-tree conversion.

Syntax support now uses CodeMirror's language catalog and loads the matching language by filename when an editor or comparison opens. Unknown names and failed language loads remain plain text. Cleanup prevents a late language load from dispatching into a closed view. Shared explicit highlight colors replace the light-background defaults. Read-only inline/split panes have named textbox roles, read-only attributes, keyboard focus and navigation bindings; editing commands cannot change their documents. Desktop acceptance covers Python keyword/string highlighting, tabbing between split panes, and attempted deletion in split/inline views while verifying the repository remains unchanged.

## Delivering streamed attribution to mounted views

The renderer subscribes to desktop events once per window. Preload validates each event and delivers it across the isolated-world bridge. A renderer-local EventTarget calls the mounted views in subscription order. Each view can unsubscribe independently, including when two subscriptions use the same function. The public preload API and the validated 64-line blame batch format stay compatible. This saves the validation and bridge copy previously repeated by each subscribed view for every blame batch. The desktop regression times the first painted line and checks the attribution at both ends of a 10,000-line file.
