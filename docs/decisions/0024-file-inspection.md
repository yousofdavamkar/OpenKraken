# Native file inspection

Commit file lists use native `diff-tree --raw -r -z --no-abbrev -M` with external diff/textconv disabled. Paths are parsed as independent NUL records and retained as base64 bytes alongside display text; rename records contain both original and destination paths. Modes, native blob IDs and similarity scores stay attached to each change. The first parent is the default comparison, a merge's other native parents can be selected explicitly, and root commits compare against the empty tree through `--root`.

The service validates commit/parent OIDs and refuses a supplied parent that is not one of the commit's native parents. File lists are bounded to 10,000 entries/16 MiB and rename matching to 1,000 candidates; execution uses the repository read queue and cancellation. Native acceptance checks renames with spaces/control characters, additions, modifications, deletion, roots and both merge parents. A seeded streaming-parser property test preserves arbitrary raw path bytes over varied chunk boundaries; malformed/truncated records are refused. Reference: [Git diff-tree](https://git-scm.com/docs/git-diff-tree).

Commit details now request these lists through typed IPC and virtualize the changed-file rows. Merge-parent selection reloads the comparison without changing history or the working tree. Requests are cancelled when the detail view changes or closes. Desktop acceptance selects both parents of a merge and checks the corresponding independent file lists; existing graph keyboard navigation remains covered.

File comparisons read immutable blob IDs from that native change list. Gitlinks are shown as submodule IDs without dereferencing them as blobs. UTF-8 text is compared with native `git diff --no-index` against private temporary files, with external drivers and text conversion disabled; the temporary directory is removed in `finally`. This keeps Git's hunk and whitespace semantics while allowing decoded text to use the same comparison path later. Original modes, paths and object IDs remain separate from the temporary diff headers. Reads and diff processes are cancellable and bounded. Binary content is reported without returning its bytes as text.

The initial text guard is 2 MiB or 10,000 lines. Explicit loading can raise it to 20 MiB or 250,000 lines, which remain hard limits; a byte guard may discover a line guard only after loading. Native service tests verify contents, hunks, whitespace options, binary classification and an explicit 50,000-line load, and check that HEAD and workspace status stay unchanged. Rendering/performance acceptance is separate from these backend tests.
