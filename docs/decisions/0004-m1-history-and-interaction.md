# 0004 — M1 history, rendering, search and navigation

Accepted 2026-11-01. Implements the requested Canvas, paging, search and keyboard work from blueprint §§4.1–4.4 and the read-only interaction spec.

History uses one retained `rev-list --date-order --parents --stdin` per active repository, with immutable start OIDs and stdout backpressure at page boundaries. There is no `--skip`, increasing max-count, or refetch of earlier pages. A page is addressed by a random cursor ID and expected commit offset; concurrent/duplicate/stale pages fail explicitly. Refresh and repository switches close the previous cursor. Page cancellation terminates its process group and requires refresh. Idle time does not count toward the 30-second active page deadline. The retained walk applies backpressure at a page boundary and caps queued records at 64 MiB. The native runner permits up to 1 GiB of streamed stdout between delivered pages. Its separate 32 MiB stderr limit applies over the lifetime of the walk. Delivering a page frees its stdout allowance so a long history can reach its root. Initial pages contain 2,000 commits; subsequent requests allow up to 5,000.

Stash rows are inserted immediately above their base when that base arrives in the retained walk. This guarantees children precede parents despite timestamp skew and works across page boundaries without loading full history. Stash index/untracked parents remain hidden. Dirty/conflicted working state is represented as a synthetic row immediately above HEAD, with a first-parent edge to HEAD. These rows do not change Git page offsets.

The worker owns lane continuation, 500-row checkpoints and an incremental MiniSearch index. Layout replies are posted before deferred indexing so display is not held up by tokenization; any search request flushes pending documents first. Appends return only new graph rows; generation/offset checks reject stale work. Refresh resets the worker, using the spec's correct off-thread full-layout fallback; suffix checkpoint reuse is deferred until a larger refresh workload justifies it. The UI paints one viewport-sized, device-pixel-ratio-aware Canvas graph column and virtualizes DOM text cells at 28 px. Search dims edges/nodes and text without removing or moving rows.

Loaded-history search uses case-insensitive token-prefix AND matching across summary/body/author/email/OID. The explicit all-history search uses Git's literal, case-insensitive message/author matching, plus unambiguous hexadecimal object prefixes, capped at 100 results. Those results can open read-only details without forcing thousands of intervening rows into the graph. The native message and author scans each have a 120-second deadline. If one fails, the service stops its sibling and waits for both before releasing the read. The desktop allows 210 seconds for the complete request, including queueing and object lookup. Search does not mutate the history cursor. The search button retains keyboard focus and becomes Cancel search while Git is running. Cancelling leaves the query, loaded matches and any page request in place. Request IDs discard late responses, including from an earlier attempt at the same query. If a background refresh is running, Cancel search also retires the queued request before Git starts. A same-repository refresh continues the queued query on its new cursor. Editing the query or switching repositories retires it. Git full-history literal matching and indexed token-prefix matching are labeled separately in the UI.

ArrowDown and j select the next row, paging when focus reaches the last loaded row. ArrowUp and k select the previous row. With Shift, the downward keys follow the first parent and the upward keys select the nearest loaded child. The H, J and K shortcuts apply while the grid has focus and accept Shift. Combinations with Ctrl, Alt or Meta remain available to other commands. Home/End select the first/last loaded row. Page Up and Page Down move by the number of whole rows that fit in the graph viewport, with a minimum of one row. Page Down continues across an append boundary and stops at the final row if the remaining history is shorter than a screen. The h key selects HEAD. Shift+H selects its upstream commit. When a branch tracks an annotated tag, the shortcut follows the tag to its commit. An upstream pointing to a tree or blob leaves the selection and loaded pages in place. Ctrl/Cmd-click toggles selection; Shift-click selects a contiguous anchor range; Ctrl/Cmd+A selects loaded rows; Escape clears selection. Enter opens read-only details; diff views remain M5. Navigation can load more pages to reach a parent or HEAD without changing previously loaded graph rows. A focusable ARIA grid keeps the active row scrolled into view and exposes selected state. Ctrl/Cmd+F focuses search; search fields retain normal text-editing keys.

This delivery does not add hide/solo/pin, network avatars, tabs, or full M1 release certification on linux.git. Existing synthetic fixture and security checks remain required; new tests cover retained paging, stale/cancelled requests, worker/search state, Canvas geometry, interaction, and Electron rendering/performance.

Responses are validated once at the utility-to-main trust boundary with the shared Zod result schema. Main and preload then forward the typed result without additional parse-and-copy passes. Page arrays are frozen before a single store assignment, avoiding thousands of Immer proxy writes while preserving previous row identities.

If a normal branch reaches a stash object, its actual commit DAG takes precedence: it is displayed once as an ordinary merge, rather than adding a duplicate projected stash row. Standalone stash overlay rows still link only to their base. Duplicate reflog entries for the same stash OID produce one overlay node.

## Object ID lookup in the active graph

The history cursor retains the exact start OIDs selected when the graph opened. A hash lookup can return a captured tip directly after resolving it to a commit. For other resolved commits, subtract the ancestry of all captured tips from the queried commit's ancestry in one native revision walk. An empty result means the commit is visible in the open graph. Pass the resolved OID and all excluded OIDs on standard input and limit output to one commit. Commits made visible only by a new ref enter the search scope when the graph refreshes. Message and author matches still contribute to the same results. [Git revision-set semantics](https://git-scm.com/docs/git-rev-list#_description)

Resolve hexadecimal queries against Git object IDs before peeling a unique match to a commit. A branch with a hexadecimal name can shadow an abbreviation in ordinary Git revision syntax. An ambiguous or absent object prefix still returns any literal text matches. Stashes follow the same prefix rule. A matched stash uses its projected base parent unless the visible Git walk reaches the actual commit, in which case search returns its native parents.

When an object ID resolves to a visible commit, put that commit first and fill the remaining results with text matches ordered by commit time. Deduplicate before applying the 100-result limit so an older commit can still be found when many newer messages cite its ID.

## Keyboard input during commit search

Enter selects the first loaded match and Escape clears the query. Both move focus to the history grid. While a text input method is composing, it owns both keys so the user can accept or cancel a candidate without leaving search. The grid acts on the initial Enter or Escape keydown. Repeats from the same held key after focus moves leave the selected row and its details alone. Arrow navigation continues to support key repeat.

## Keyboard navigation across a page boundary

Down on the last loaded row selects the first appended row when more history exists. A jump can wait for the page already loading under the pointer or request another page if its target lies farther back. A newer navigation request, a changed selection, or a different snapshot cursor supersedes the pending jump. A failed or cancelled page that adds no rows ends the jump.

Selection retains the last known row positions for its focus and range anchor. A lookup uses a position only when the row still has the selected commit ID. Refresh rebuilds positions from the new rows. This keeps adjacent keyboard navigation and short range selections near the end of a long history proportional to the number of rows selected. The Canvas obtains each visible node's working-tree or linked-worktree style from the display row at the same position as its graph row.

The grid passes its known focused index to keyboard navigation. Home, End, page keys and ordinary arrows can select loaded positions directly. Shift+Up scans backward to the nearest child. Parent and ref jumps resolve commit IDs. While a jump waits for an append, it remembers how many rows it has checked and resumes at the first new row. If a working-state refresh replaced the earlier rows, the jump rechecks the projection.

When keyboard navigation targets the already focused commit, bring its row back into view even if the user has scrolled away. Ordinary scrolling can leave the selection offscreen until the next navigation command. The grid publishes its active descendant only while that row is mounted. Its accessible description gives the loaded commit count and whether more are available. While a further page exists, the total row count is unknown. After the final page, the grid reports every displayed row, including linked checkouts and working-tree rows. [WAI-ARIA grid and table properties](https://www.w3.org/WAI/ARIA/apg/practices/grid-and-table-properties/#usingaria-rowcountandaria-rowindex)

## Starting the graph worker on repository open

Start the candidate worker while the repository request is pending. A same-repository refresh uses the existing worker and its lane checkpoints. During a switch, keep the displayed worker until the candidate has returned its first layout. Close the candidate if opening, layout or cancellation ends the request before publication. A worker load failure is retained so the first layout request can report the error immediately.

Once the renderer sends the page to the graph worker, it freezes the validated snapshot and display rows and collects the IDs used to restore selection. The worker has its own structured clone. The current snapshot, layout and selection stay visible together until the worker returns a valid layout for the pending request.

If the displayed worker reports a fatal error, the next repository refresh builds a fresh worker from the returned snapshot. The renderer retains the query and selection for the same checkout and reconstructs the search index and lane checkpoints. The desktop regression terminates the worker during a search, reports its error, refreshes and reads the next native page.

A timed-out layout request also retires the worker. The worker may already have advanced its generation or append offset when the renderer loses the reply. Refresh then rebuilds the graph from the native snapshot. A timed-out search can discard its late matches and accept the next query on the same worker.
