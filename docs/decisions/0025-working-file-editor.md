# Working-file editor

Working-file previews and saves use the existing repository queue, index lock, file-backup layer and Undo journal. The editor selects existing regular files from the working-tree status. It refuses active Git operations, links, directories, unsafe paths, binary/undecodable content and files beyond 2 MiB or 50,000 lines. The save token binds raw file bytes/mode, the Git HEAD/index fingerprint, and the effective encoding attribute. A stale token refuses the save rather than replacing newer edits. Raw replacements preserve mode, leave the index unchanged, and produce a reversible journal entry backed by bytes outside Git.

Native `check-attr -z --stdin working-tree-encoding` is authoritative for encoded worktree files. Otherwise the bounded display decoder determines the encoding. Supported UTF-16 BOM aliases map to the explicit endian codec; unsupported attribute values are refused. Both the original preview and proposed output must round-trip through the selected encoding without byte/character loss. BOM state is retained, and the backend saves the exact submitted line endings. No clean/smudge filter or staging operation runs as part of an editor save. Public behavior reference: [Git attributes](https://git-scm.com/docs/gitattributes), [Git check-attr](https://git-scm.com/docs/git-check-attr).

Native tests cover CRLF, executable mode, unchanged staged contents, Undo/Redo, external edits, index changes, UTF-16LE-BOM attributes, lossy legacy output, changed attributes and symlink refusal. As with the existing backup-backed operations, filesystem checks are optimistic: they do not provide an atomic transaction against arbitrary concurrent external filesystem writers. Pending journal records retain recovery evidence for uncertain failures; M8 owns the broader crash-recovery audit.
