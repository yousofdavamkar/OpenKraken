# Create a personal provider repository

From Provider accounts, the user chooses a connected account and reviews its host, login, repository name and visibility. Creation defaults to private and an empty repository. A description, public visibility and an initial README are explicit choices. The main process resolves the credential from the protected store and revalidates the account ID and login before dispatch. The renderer supplies a repository name. The service derives the API endpoint from the connected account.

GitHub and GitHub Enterprise use the authenticated user's repository endpoint. GitLab uses the projects endpoint with the requested name and path and omits the namespace ID to select the user's personal namespace. A successful creation requires HTTP 201, a valid repository ID, the requested owner, name and visibility, and the authenticated user's ID wherever the provider returns an owner ID. The clone URL uses the configured host and the validated repository path. [GitHub repository creation](https://docs.github.com/en/rest/repos/repos#create-a-repository-for-the-authenticated-user) · [GitLab project creation](https://docs.gitlab.com/api/projects/#create-a-project)

A connection can fail after the provider receives the write. An uncertain result keeps the request visible and changes the form's primary action to a read-only lookup of that exact personal repository. A failed lookup leaves the check available. A successful lookup shows the current visibility and clone URL as a found repository. The lookup establishes its present state. The user can return to editing explicitly. The existing clone picker also provides access after the dialog closes. [GitHub repository lookup](https://docs.github.com/en/rest/repos/repos#get-a-repository) · [GitLab Projects API](https://docs.gitlab.com/api/projects/)
