# Reviewed interactive rebase sessions

The bundled native helper has a separate editor mode. It sends the requested path to a per-invocation service socket authenticated by a random 256-bit capability. The service owns file validation and writes; the helper returns success only after the service acknowledges the edit. It writes no commit contents to stdout or stderr. Unix socket directories/files have 0700/0600 permissions; Windows uses the existing named-pipe transport. Closing or cancelling the invocation revokes the capability and aborts its pending edit. Message size, connection count and elapsed time are bounded.

Native helper tests cover approved file writes, wrong/expired capabilities, rejected paths and pending-request cancellation. Authentication uses a separate protocol and remains covered by its existing native tests.

The service now reviews a linear ancestor-to-HEAD range of 1–500 commits, bounded to 2 MiB of messages/plan data. Start rechecks the token under the index lock and requires every reviewed OID exactly once; drop is explicit and squash/fixup require an earlier retained commit. Native Git owns replay, hooks, signing, conflict state and progress. Autosquash, autostash, merge preservation and update-refs are disabled explicitly, and empty commits are retained. Nonlinear ranges and non-ancestor bases are currently refused with an actionable message.

The helper automatically edits the native todo and COMMIT_EDITMSG in the canonical repository Git directory. It rejects symlink redirection, hard-linked metadata and oversized metadata. Other documents require the fallback review described below. Todo lines contain only validated action/OID pairs. Messages are selected from the reviewed plan using native `done` progress; a final fixup retains the latest reviewed squash message in that chain. Paused plans live in the profile's integration origin record and are reattached only to the same native operation after restart. An explicit native edit stop allows the existing Amend action; ordinary commits remain blocked during rebase. Completed interactive rebases use the integration Undo checkpoint.

Native acceptance covers reorder, reword, drop, squash/fixup chains, edit-stop amendment, conflict resolution and restart before a later reword. Invalid and stale plans are refused before mutation. References: [Git rebase](https://git-scm.com/docs/git-rebase), [Git editor variables](https://git-scm.com/docs/git-var).

The desktop editor now exposes the base review, ordered native commit list, action selectors and reviewed message fields through typed IPC. Both drag ordering and keyboard-accessible Move up/down buttons are available. Invalid initial squash/fixup and missing messages disable submission. Starting a rebase participates in watcher suspension, cancellation and operation timeout handling. Edit-stop guidance points to the existing Amend form; other active operations disable ordinary commit/amend submission. Desktop acceptance checks that planning leaves HEAD untouched, reordered/reworded/dropped history matches the review, Undo restores the starting tip, and Edit → Amend → Continue returns to the branch.

The fallback editor supports additional regular UTF-8 documents inside the repository's canonical Git metadata directory (up to 1 MiB). A typed request-scoped prompt displays the original text and requires Save and continue or Cancel edit. Replies must match both the operation ID and prompt ID. Closing/cancelling the native editor revokes the prompt; draft text is not persisted by the renderer. Before saving, the service reopens the file and compares its filesystem identity and original contents. Newer edits, binary content, hard links, symlink redirection and paths outside the Git directory are refused. These remain optimistic filesystem checks, consistent with the other native operation guards.

Native tests cover successful review, cancellation, concurrent edits, out-of-scope paths, binary and hard-linked files. Desktop tests exercise both Save and Cancel while native Git waits for its editor. The fallback deliberately does not grant a native editor request arbitrary filesystem access outside the selected repository's Git metadata.
