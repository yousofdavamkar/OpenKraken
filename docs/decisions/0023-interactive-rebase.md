# Reviewed interactive rebase sessions

The bundled native helper has a separate editor mode. It sends the requested path to a per-invocation service socket authenticated by a random 256-bit capability. The service owns file validation and writes; the helper returns success only after the service acknowledges the edit. It writes no commit contents to stdout or stderr. Unix socket directories/files have 0700/0600 permissions; Windows uses the existing named-pipe transport. Closing or cancelling the invocation revokes the capability and aborts its pending edit. Message size, connection count and elapsed time are bounded.

This is the transport slice; callers must constrain requested paths to their reviewed native Git session. Todo editing, commit-message selection, persistent plans and the interactive UI are subsequent slices. Native helper tests cover approved file writes, wrong/expired capabilities, rejected paths and pending-request cancellation. Authentication uses a separate protocol and remains covered by its existing native tests.

The service now reviews a linear ancestor-to-HEAD range of 1–500 commits, bounded to 2 MiB of messages/plan data. Start rechecks the token under the index lock and requires every reviewed OID exactly once; drop is explicit and squash/fixup require an earlier retained commit. Native Git owns replay, hooks, signing, conflict state and progress. Autosquash, autostash, merge preservation and update-refs are disabled explicitly, and empty commits are retained. Nonlinear ranges and non-ancestor bases are currently refused with an actionable message.

The helper may edit only the native todo or COMMIT_EDITMSG in the canonical repository Git directory. It rejects symlink redirection, hard-linked metadata, unexpected paths and oversized metadata. Todo lines contain only validated action/OID pairs. Messages are selected from the reviewed plan using native `done` progress; a final fixup retains the latest reviewed squash message in that chain. Paused plans live in the profile's integration origin record and are reattached only to the same native operation after restart. An explicit native edit stop allows the existing Amend action; ordinary commits remain blocked during rebase. Completed interactive rebases use the integration Undo checkpoint.

Native acceptance covers reorder, reword, drop, squash/fixup chains, edit-stop amendment, conflict resolution and restart before a later reword. Invalid and stale plans are refused before mutation. The editor UI and typed requests are the next slice. References: [Git rebase](https://git-scm.com/docs/git-rebase), [Git editor variables](https://git-scm.com/docs/git-var).
