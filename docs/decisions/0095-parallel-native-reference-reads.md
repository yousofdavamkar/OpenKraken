# 0095 — Parallel native reference reads

The metadata strategy and nine-field format below are superseded by [ADR 0097](0097-selective-reference-object-metadata.md). The pagination capability probe, coverage checks and complete-enumeration fallback remain in use.

Large reference snapshots spend most of their native time reading subjects and peeled object metadata. Keep those fields and the existing complete-snapshot contract. For repositories with at least 10,000 refs, use bounded native pagination to parallelize this work when the selected Git supports it.

Read an ordered identity list containing names, object IDs, upstream names and HEAD markers. Probe `for-each-ref --start-after=` at runtime; an unsupported-option exit selects the original single-command path for subsequent reads. This preserves Git 2.38 compatibility without assuming that a version string implies a capability. Git documents the pagination option in its [2.51 manual](https://git-scm.com/docs/git-for-each-ref/2.51.0). Do not combine it with an explicit sort or pattern arguments.

Divide the observed list into three contiguous pages. Each command uses its preceding name as an exclusive marker and a bounded count, retaining the full nine-field format and existing parser. Three jobs fit the service's existing three-process pool. Returned page order is the native reference order, regardless of completion order. Re-read identities afterward and compare both the raw identity list and the returned records' names, targets, HEAD markers and upstream names. A detected change, missing record or shifted boundary discards the paged result and performs one ordinary complete enumeration. Do not loop indefinitely under an external writer. Ahead/behind counts are read in the full records; identity checks do not repeat their ancestry walks.

Keep a shared 32 MiB stdout/stderr limit across the full-record pages, individual limits on identity/probe commands and a 30-second deadline for the entire reader. On cancellation or any page failure, abort and await every outstanding page before returning to the repository queue. Do not publish partial pages. Non-UTF-8 identity output and markers over 4,096 bytes select the original command so Node argument encoding and platform command-line limits cannot omit refs. Small repositories also use the original full-record command after the inexpensive identity read.

These checks detect observed changes; they do not make independent Git reads an atomic transaction or exclude external writers. Changes that are made and reversed between checks, configuration/object-store races and platform-specific execution remain outside that claim. Existing watcher refreshes and operation-specific mutation checks remain necessary.

Native fixture tests compare every returned field with one ordinary `for-each-ref` call, including annotated/non-commit tags, symbolic remote refs and Unicode. They cover concurrent additions/deletions/moves, HEAD changes, upstream configuration and tracking-tip changes, unsupported-option fallback, cancellation/failure cleanup, aggregate output limits and non-UTF-8 names. The unsupported-Git case simulates its option error while running the fallback through real Git; it is not native Git 2.38 runtime evidence.

The 50,000-ref Linux fixture improved to 1.69–1.71 seconds first paint, with passing paging/scroll bounds, but still misses the 500 ms gate. See the [performance report](../verification/m8-reference-performance.md). This is a performance increment, not M8 completion.
