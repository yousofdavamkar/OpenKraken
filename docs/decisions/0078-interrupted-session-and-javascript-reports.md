# 0078 — Interrupted-session and JavaScript reports

[ADR 0077](0077-opt-in-crash-summaries.md) establishes the fixed-field, opt-in reporting boundary. Extend its coverage without collecting exception text or native memory.

After the single-instance lock succeeds, initialize reporting before the rest of the ready-time startup work. For an opted-in session, atomically write a private `reporting-session.json` marker containing only a schema version, a local ownership nonce, the current consent revision and the validated app/OS/architecture metadata. No repository information or session contents enter this file. Normal `will-quit` cleanup and opt-out remove the marker owned by that instance. A canceled window close does not clear it.

On the next launch, a valid marker matching current consent may produce one `main/unclean-exit` event using the previous app release. Replace it with the new session's marker before attempting delivery. Failed delivery is not queued for retry. An unclean exit can mean a crash, forced termination, power loss or interrupted cleanup; it is a warning, not proof of an application crash. Missing, changed, corrupt, oversized or redirected marker state is never used as arbitrary report content. Unsupported recovery state disables reporting for that session and preserves the original file.

Consent schema version 2 requires a new explicit opt-in for this expanded behavior. Read valid version-1 consent as disabled, preserving its revision so the user can review and save the new choice. Each consent save gets a fresh local nonce; disabling and later re-enabling cannot authorize a marker from an earlier consent period. Neither consent nor session nonces are transmitted. Renewing consent cancels an in-flight attempt from the old generation and resets its delivery status.

Observe main JavaScript exceptions through Node's [`uncaughtExceptionMonitor`](https://nodejs.org/api/process.html#event-uncaughtexceptionmonitor), without replacing default exception handling or inspecting the Error object. A promoted unhandled rejection receives a separate fixed category. If the process exits before asynchronous reporting can run, its interrupted-session marker supplies the generic next-launch summary. Do not add an `unhandledRejection` handler that changes Node's default fatal/warning behavior.

Renderer global `error`/`unhandledrejection` events and the React error boundary submit only one of two literal reason strings. A strict, trusted-frame IPC route fixes the process category to renderer; it accepts no message, stack, filename, process override or destination. Reporting failures are caught to prevent recursive error events. Existing error propagation and default handling remain in place. JavaScript events use error severity, native process failures retain fatal severity, and interrupted-session summaries use warning severity. All existing consent, destination, concurrency, deadline and attempt limits still apply.

Tests cover marker ownership, original-release recovery, clean shutdown, consent changes, migration, corrupt/symlinked files and renewal cancellation. Linux desktop acceptance generates real renderer errors, unhandled promise rejection, a main exception, a Git-utility crash, a renderer crash and main-process SIGKILL against the local trusted HTTPS receiver. Private sentinel strings in the exceptions must not appear in any report. Restart after normal shutdown must not produce an interrupted-session event, and the disconnected default build creates neither consent nor session-marker files.

This does not capture native startup failures before JavaScript/reporting initialization, preserve reports across a failed disk write, identify the cause of an abrupt exit, collect native dumps or detailed stacks, or guarantee delivery before termination. Main promise rejections are observed only when Node promotes them to monitored exceptions. Worker-specific JavaScript failures and every React failure path are not separately exercised. Actual Sentry project acceptance, Windows/macOS runtime evidence and beta feedback remain outstanding.
