# Provider repository picker

GitHub and GHES repository browsing uses the connected account's protected credential in main. Each page first validates the account identity, refreshing an expiring device credential through the existing protected rotation path. Public results contain repository metadata only. The shared request wrapper retains HTTPS verification, cookie omission, redirect refusal, cancellation, timeouts, body bounds and fixed public errors.

The picker requests `GET /user/repos` ordered by full name, ascending, in pages of 100. It includes repositories accessible to the token under the endpoint's default affiliations. A full page permits the next numbered page; this can make one extra empty request when the total is a multiple of 100. It never follows server-supplied pagination URLs. Browsing stops at 100 pages (10,000 entries) with an explicit limit message. The provider can change between requests, so the desktop deduplicates IDs while appending pages; Refresh starts a new list. Search filters loaded metadata, rather than claiming to search all provider repositories.

Clone URLs are constructed from the configured HTTPS origin and validated literal owner/repository path segments. Provider-supplied clone URLs, pagination links and extra fields are not trusted or forwarded. Repository IDs must be positive safe integers before string conversion. Malformed pages fail with a fixed error. Selecting a repository fills the existing clone form. Saved-account authentication is now provided by [the native Git authentication boundary](0029-provider-git-authentication.md); users can also choose the existing Git credential-helper flow.

Reference: [GitHub repository REST API](https://docs.github.com/en/rest/repos/repos#list-repositories-for-the-authenticated-user).

The Clone dialog now exposes the account selector, a virtualized single-selection list with arrow/Home/End/Enter navigation, loaded-result search, explicit next-page loading and refresh/retry controls. Switching accounts replaces the list and cancels the old request; hiding/closing the picker also cancels pending work. Obsolete responses cannot repopulate the list. The active option remains mounted for `aria-activedescendant` even when virtual scrolling moves the viewport. Selection fills the existing URL field and preserves the native destination-folder and clone-options flow.

MSW service fixtures cover GitHub/GHES paging, protected refresh during browsing, canonical URL construction, malformed metadata, page/response limits and refusal to follow foreign pagination links. Electron fixtures cover paging with duplicate IDs, bounded mounted rows, search, keyboard choice, account-switch/close cancellation, sanitized errors and retry. A selected canonical URL is cloned by real native Git with a fixture-only URL rewrite to a deterministic local source; this establishes the desktop selection-to-clone flow, not live provider transport or automatic provider-token use by Git.
