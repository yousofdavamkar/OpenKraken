# 0087 — Verify restart helper readiness before shutdown

AppImage replacement must not close the working app and replace its executable before discovering that the native restart helper cannot start. Main now starts the copied, trusted helper during installation preparation, while the current window and installed image remain intact. A bounded readiness handshake must complete before requesting application shutdown. A missing, silent or malformed helper fails preparation, discards staging, retains the verified download and offers a fresh installation identity.

The update controller supplies a cloned, main-only restart plan from the prepared transaction: original filename, signed replacement size/hash, predecessor size/hash and journal hash. It is not an IPC request or renderer-selected executable. Preparation retains the helper connection without arming it. The existing unsaved-work prompt can therefore keep the app open without starting a replacement or consuming the helper's parent-exit deadline.

Accepted shutdown arms this already-ready helper and waits for its acknowledgement before committing the file replacement. Readiness and arming each have a 750 ms bound; ordinary service shutdown uses a 1,500 ms deadline. [ADR 0120](0120-appimage-shutdown-and-confirmation.md) defines the separate deadline for the final installation commit. The helper still waits for the actual parent to exit and verifies the installed replacement before execution. Its startup supervision and verified predecessor restoration follow ADR 0086.

Keep editing, explicit cancellation and an ordinary quit during preparation abort the pending handshake or terminate the waiting helper. The old parent is still alive, so the helper cannot yet have launched a replacement. Cancellation of a queued restart also revokes the scheduled quit and releases installation admission. Concurrent cancellation requests share one transaction-discard operation; they cannot remove the same staging files twice or issue conflicting installation identities. A failed arm cancels the helper and abandons installation before replacing the executable.

Tests exercise real helper readiness, delayed arming, cancellation and abort signals, plus missing, silent, malformed, stopped and non-arming helper fixtures. Controller coverage checks isolated restart-plan values and overlapping cancellation. Disposable packaged acceptance substitutes a missing helper executable only in the fixture build and checks that the current application remains open, the installed image is unchanged, staging is removed and another install is admitted. The ordinary fixture also injects cancellation before the queued quit, then exercises Keep editing and accepted restart. Production contains no test switch or spawn override.

This reduces failures discovered after closing the window; it is not a guarantee against helper death after readiness or arming, process termination during commit, physical power loss, interrupted recovery or incompatible profile migrations. A helper that stops before arming is rejected before replacement. After the old process exits, unexpected helper failure can still require manual relaunch and recovery. Hung or unconfirmed replacement processes retain the behavior and limitations recorded in ADR 0086. Native Windows/macOS installation remains outside this AppImage implementation.
