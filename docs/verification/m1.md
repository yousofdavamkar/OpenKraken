# M1 Canvas, paging, search and navigation verification

Follow-up: [ref controls and checkpoint refresh](m1-views.md) supersede the deferrals for those features below.

Verified locally on Linux x64, 2026-11-01. React 19.3.1, TypeScript 7.0.2, Electron 45.2.1 and MiniSearch 7.2.0.

## Delivered

- A device-pixel-ratio-aware, viewport-sized Canvas graph column beside virtualized accessible DOM cells. Lane layout and search run in a Web Worker.
- Append-only paging from one retained, backpressured `rev-list` process. Pages carry cursor/generation and offset checks, preserve existing graph rows, and stop cleanly on cancellation or refresh. Initial page: 2,000 commits; subsequent pages: up to 5,000.
- Incremental MiniSearch indexing with dimmed non-matches; no row removal or relayout. Separate Git-backed literal message/author search and hash lookup find commits beyond the loaded pages. Results are capped and labeled.
- Single/range/toggle selection, arrows and page navigation, first-parent/nearest-child shortcuts, HEAD/upstream shortcuts, select-all/clear, and Enter/double-click details. Search inputs retain normal editing behavior.
- Synthetic WIP/conflict rows, branch/tag badges, and stash projection across page boundaries. A branch reaching a stash object retains its actual DAG without duplicate overlay nodes.
- Worker replacement on refresh, stale-response guards, bounded retained-record memory, and six Canvas image goldens.

The retained-stream test verifies exactly one rev-list invocation across multiple pages and compares all 7,300 returned OIDs with Git. Moving a branch between pages does not change the cursor's history; refresh starts a new walk and rejects the old cursor. Tests cover cancellation, stale offsets, end-of-history, stash boundaries, full-history search, and duplicate stash reachability.

Worker tests compare append results with the pure one-shot allocator and preserve previous row identity. They verify incremental indexing, generation/offset rejection, and duplicate rejection. UI store tests cover late pages after refresh, late search responses after query changes, wrong offsets, and stable selection. Canvas geometry tests verify connected segments and viewport/DPR bounds.

Electron tests drive real native-picker selection (stubbed only to choose a temporary fixture), the actual Git utility process, the real Web Worker, scrolling, search, keyboard navigation and refresh after an external commit. The first-paint gate includes Git/IPC, worker layout, React/Canvas and two animation frames, with a 500 ms limit. The 5,000-row paging gate includes Git/IPC, worker layout and immutable store update, with a 300 ms limit; search indexing is deferred after the layout reply and flushed before any query. Scrolling records 60 frame intervals after loading 12,000 commits and enforces fewer than 100 mounted DOM rows. These are synthetic-fixture measurements on this host, not linux.git certification.

Canvas image goldens cover linear, merge, octopus, criss-cross, orphan and stash fixtures. They use a fixed 420 CSS-pixel viewport and CSS screenshot scale to avoid platform-specific image dimensions. The final run compares committed baselines without updating them. Existing renderer isolation, CSP and fuse checks remain green.

Generated evidence is under `test-results/`: `e2e.json`, `graph-merge.png`, `graph-large.png`, `repository.png`, `packaged-shell.png`, and attached paging/scroll measurement JSON. The runnable Linux package is under `release/OpenKraken-linux-x64/`.

## Scope and limits

This completes the requested Canvas, append-only paging, search and keyboard work. Remaining M1 items include hide/solo/pin controls, optional network avatars, checkpoint-aware refresh reuse, and the linux.git/large-real-repository benchmarks. Refresh uses a correct worker reset rather than suffix reuse. Enter opens read-only commit details; diff views remain M5.

The configured macOS/Windows CI matrix has not run in this session. Signing, installers, platform-specific ASAR integrity enforcement and actual Git 2.38 compatibility still require their respective release runners. Package smoke verifies startup/isolation; the development Electron E2E suite verifies the complete graph flow.
