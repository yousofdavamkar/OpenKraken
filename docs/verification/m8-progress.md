# M8 progress — hardening and release

M8 remains in progress. The current checkpoint adds unsigned Linux AppImage generation and runtime acceptance after DEB/RPM packaging, main/PTY crash acceptance, interrupted native-prompt recovery, local commit drafts and native command supervision. It does not establish release completion or close the remaining [M6](m6-progress.md) and [M7](m7-progress.md) scope.

## AppImage pipeline

The AppImage target wraps the hardened Linux bundle with an independently written launcher (`d6a577a`). It pins producer/runtime downloads by SHA-256, preserves all original payload bytes and permissions, includes explicit unsigned/test metadata and the upstream runtime notice, and records the complete AppDir manifest. The launcher preserves arguments, cwd and exit status and never adds sandbox-disabling flags. See [ADR 0076](../decisions/0076-appimage-launch-and-verification.md).

The final Linux x64 AppImage built successfully and passed archive/payload/fuse checks plus desktop smoke through its actual runtime in both normal FUSE and extraction modes, with explicit `APPIMAGE_BUILD_EXIT=0`, `FUSE_SMOKE_EXIT=0` and `EXTRACT_SMOKE_EXIT=0`. Both modes exercised renderer isolation, native helpers, native folder selection, repository opening, Bash command tracking, keyboard delivery and terminal exit. The launcher contract test and rejection of altered archive/native-helper hashes passed. Full ESLint/Prettier and a DEB verifier/desktop regression smoke passed (`DEB_REGRESSION_EXIT=0`). No app TypeScript or dependency versions changed; the native/unit suite and full Electron suite were not rerun for this packaging-only increment.

The initial command rejected the unimplemented target. Artifact verification then caught a writable icon mode; generation now sets it to 0644. Extraction-mode UI checks initially passed but test cleanup orphaned Electron by killing only its runtime supervisor. The smoke now identifies the actual browser PID through CDP and terminates it before waiting for the runtime. Its existing two-second shutdown bound now fails if forced cleanup is required. The first stalled smoke required manual cleanup and is not independent passing evidence. Later complete runs exited normally, and a process trace confirmed the runtime waited for Electron and exited. Runtime extraction files are isolated under disposable build/test directories, because this pinned runtime left files behind during local testing.

Evidence: `/tmp/openkraken-appimage-red.log`, `/tmp/openkraken-appimage-launcher-{red,green}.log`, `/tmp/openkraken-appimage-final-build.log`, `/tmp/openkraken-appimage-final-{fuse,extract,guards,lint}.log`, `/tmp/openkraken-appimage-cleanup-trace.log` and `/tmp/openkraken-appimage-deb-regression.log`. The artifact and unsigned manifest are under `release/installers/linux-x64/test/AppImage/`. CI is configured for both launch modes and negative checks; remote CI execution remains unverified. AppImage does not install host dependencies or system launcher integration. ARM64 execution, restricted user-namespace environments, broader distribution acceptance, signing and update delivery remain open.

## Linux installer pipeline

Linux bundle hardening (`111d798`) normalizes executable/directory modes to 0755 and other files to 0644. The installer pipeline (`67f9df1`) wraps a copy of the hardened bundle in DEB/RPM, compares original files/modes/links and fuses, rejects unsafe permissions and unexpected changes, and emits an unsigned artifact manifest. Test metadata is explicit and uses reserved addresses; actual release maintainer, homepage and license details remain pending. See [ADR 0074](../decisions/0074-linux-installer-payload-verification.md).

Both final Linux x64 artifacts passed archive/payload verification, Git dependency and desktop-entry checks, fuse verification and packaged desktop smoke with explicit `DEB_SMOKE_EXIT=0` and `RPM_SMOKE_EXIT=0`. Smoke covers renderer isolation, native askpass/editor helpers, the native folder picker, repository opening, Bash integration, keyboard delivery and terminal exit. A fresh hardened platform bundle passed the same smoke. Checksum and native-helper payload mismatches were deliberately rejected before app launch. These manifests are not signatures.

The fresh Debian 13 fixture exposed a real compatibility bug: the host-built terminal module required `GLIBC_2.42`, while Debian provides 2.41. Linux packaging now rebuilds the staged Node-API terminal module in a pinned Debian compiler image (`26eab3d`), leaving development dependencies untouched. The original module fails and the rebuilt module passes the same library check. The final portable DEB passed fresh installation, shared-library resolution, desktop registration, replacement guards, same-version reinstall, removal, purge and user-data retention with explicit `LIFECYCLE_EXIT=0`. System CA certificates are now required by both installer formats. See [ADR 0075](../decisions/0075-linux-native-build-baseline.md).

The increment also passed **593 native/unit tests in 77 files** with Git LFS enabled and explicit `UNIT_EXIT=0`, typechecking/build, frozen dependency installation and full ESLint/Prettier. The initial unit run passed 562 with 31 opt-in tests skipped; enabling the existing LFS fixture produced the complete 593-test result. This increment did not rerun the complete Electron suite, real-repository performance, live-provider acceptance or macOS/Windows/arm64 runtime gates.

Artifact checks caught RPM 6's default archive format incompatibility and writable modes inherited from Electron's ZIP. The pipeline now selects RPM v4 with SHA-256 file digests, normalizes bundle permissions, and preserves explicit archive modes while creating implicit extraction directories under umask 022. Runtime dependencies supplement builder defaults. Removal hooks skip replacement phases so an older RPM's removal hook cannot unregister its replacement's launcher.

## Crash and prompt recovery

Linux crash acceptance (`d211bf5`) now kills the main app during a stalled native fetch, observes transport closure before fixture-server cleanup, restarts with an unknown activity outcome and recovers an acknowledged commit draft. Main-app and terminal-utility death also terminate the PTY shell and its ordinary foreground command. These scenarios already passed with native supervision and Electron/PTY lifecycle behavior; no new process-termination mechanism was needed for them.

A separate service-crash test reproduced lost unsaved text in the native Git document editor. The correction (`d164003`) reports interrupted request identities from main before resolving service-exit errors; the editor retains its live textarea for copying and explicit discard, removes continuation actions and protects window closure with the existing unsaved-changes prompt. Escape does not discard it. Native authentication prompts are removed and replacement services reject stale editor/password replies. Error messages describe uncertain partial completion and require inspection before retrying. The same interruption event is emitted on a service deadline; that long-deadline path was not separately advanced in these fixtures. See [ADR 0073](../decisions/0073-interrupted-native-prompts.md).

Verification passed **593 native/unit tests in 77 files** with explicit `UNIT_EXIT=0`, typechecking/build, full ESLint/Prettier with explicit `LINT_EXIT=0`, and **50 targeted desktop tests** with explicit `E2E_EXIT=0`. Coverage includes five new crash/prompt scenarios plus service shutdown, activity, commit drafts, authentication, rebase, operations, terminal, working-tree and graph regressions. Paging measured **150.7 ms** and 12,000-row scrolling **16.8 ms p95**; six graph visual goldens passed unchanged. The interrupted-editor screenshot was visually inspected. No timeout or budget was relaxed. This increment did not rerun packaging, the complete desktop suite, live-provider acceptance or cross-platform runtime checks.

Evidence is `/tmp/openkraken-main-crash-{fetch,pty,types}.log`, `/tmp/openkraken-prompt-crash-{red,green,retain-build}.log` and `/tmp/openkraken-crash-final-{unit,lint,build,e2e}.log`. The parent/PTY crash fixtures passed initially; the native-editor retention test failed before the correction. Recovery text remains in the surviving renderer only. This does not establish persistent native-editor drafts, cleanup of intentionally detached or signal-ignoring terminal commands, arbitrary write rollback or native lock recovery.

## Local commit drafts

Main-only draft persistence (`9ff7aa5`) and the commit-form integration (`e874b32`) save separate normal/amend text and signing choices for each checkout. Acknowledged text survives a forced renderer crash and app restart. Changed-HEAD amendment remains blocked until review; failed commits and edits made during a running commit retain text. Successful amendments keep the separate next-commit draft. Revision checks reject stale saves, and corrupt, externally changed or redirected storage is preserved with a warning. See [ADR 0072](../decisions/0072-local-commit-drafts.md).

The increment passed **592 native/unit tests in 77 files** with explicit `UNIT_EXIT=0`, typechecking/build, full ESLint/Prettier, and four focused Electron scenarios with explicit `E2E_EXIT=0`. The restored-draft screenshot was visually inspected. Native contract tests cover strict main-only routes and bounded payloads. Electron coverage includes renderer crash/restart, successful clearing, failed hooks, newer edits during a blocked commit, linked-worktree separation, amend toggle retention, changed-HEAD refusal, unknown identities, stale saves, private file permissions, external changes and corrupt/symlinked storage.

The subsequent **complete desktop suite passed 163 tests**, with one opt-in real-repository benchmark skipped and explicit `E2E_EXIT=0`. Native Git LFS 3.8.1 and the local Gitea HTTPS/SSH fixture were enabled. First paint for 2,000 commits measured **266.0 ms**, a 5,000-commit page **162.7 ms**, 12,000-row scrolling **16.7 ms p95**, the 50,000-line comparison **498.6 ms**, and 10,000-line blame first screen **257.1 ms**. Six graph visual goldens passed unchanged. These are Linux fixture measurements; the skipped real-repository benchmark and cross-platform runtime gates remain open. Full-suite evidence is `/tmp/openkraken-drafts-full-e2e.log`.

A fresh unsigned Linux x64 package passed fuse verification and packaged smoke checks with explicit `PACKAGE_EXIT=0` and `SMOKE_EXIT=0`: renderer isolation, native askpass/editor helpers, the native folder picker, repository opening, Bash integration, keyboard delivery and terminal exit. Evidence is `/tmp/openkraken-drafts-{package,smoke}.log`. This smoke checks packaged startup and existing native integrations; draft crash/restart scenarios were exercised in the Electron suite above, not against the packaged executable.

The first test reproduced missing persistence. A later test reproduced edited amend text being replaced on toggle; that behavior is corrected. A changed-HEAD fixture originally created an empty commit that native Git correctly refused to amend; it now creates a content change. Playwright retained a crashed page handle after native reload, so crash recovery is verified through app restart. No performance budget or timeout was relaxed. Evidence is `/tmp/openkraken-drafts-{red,green,amend-red,guards,amend-diagnostic,crash-green,recovery-green,unit,types,lint,recovery-build}.log`.

Draft files are local plaintext. The UI distinguishes pending, acknowledged and failed saves. Crashes before acknowledgment can lose the newest edits, and a crash after Git succeeds but before draft clearing can restore already-submitted text. This does not establish a transaction journal, native lock recovery or durability for other editors/composers.

## Native command supervision

The Git utility configures the bundled native helper before starting Git discovery or repository commands. Each command receives a supervisor that retains its process-group identity on POSIX or joins a private Windows Job Object. Parent death stops ordinary active descendants. Existing argument vectors, environment isolation, streamed output, cancellation and deadlines remain in place. See [ADR 0071](../decisions/0071-native-process-supervision.md) for platform behavior and limitations.

A native fetch to a stalled local HTTP endpoint reproduced the leak before the change: its connection remained open after the Git utility died. The same regression now observes closure before the server releases any connections and reopens the repository through a replacement service. A Linux commit-hook fixture kills the utility while a signal-ignoring hook and its child are active; both stop and HEAD, index entries and staged content remain intact. This particular fixture does not establish rollback or lock recovery for arbitrary interrupted writes.

## Remaining work

- Native supervision runtime acceptance on Windows/macOS, further crash/write scenarios beyond the Linux fetch/PTY/prompt fixtures above, native lock handling and durable write recovery. POSIX processes that intentionally detach or daemonize beyond the active command's stream lifetime are not contained.
- Durable drafts for working-file, conflict/native editors and provider composers; commit-form drafts are implemented within the bounds above. Opt-in crash reporting, signature-verified updates, signed installers/distribution, security review and beta evidence remain open.
- DMG/MSI, RPM distribution install/upgrade/remove acceptance, broader AppImage distribution acceptance, Linux arm64 and macOS/Windows installer runtime checks, and real release metadata. DEB/RPM/AppImage artifacts in this checkpoint remain unsigned local test builds.
- Broader real-repository and cross-platform performance/regression gates, plus the unresolved intermittent command exit-143 investigation recorded in M7 progress.

Interrupted operations retain an unknown activity outcome. Process cleanup does not prove that a remote write failed, reverse completed changes or authorize an automatic retry. Linux fixtures and an unsigned local bundle do not establish production release readiness.
