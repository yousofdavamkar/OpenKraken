# M0 and initial M1 verification

Verified locally on Linux x64, 2026-11-01, with Node 24.22.2, pnpm 11.25.0, Git 2.53.0, Electron 45.2.1, React/React DOM 19.3.1, and TypeScript 7.0.2.

## Delivered

- pnpm monorepo, TypeScript project references including tests, ESLint/Prettier, frozen lockfile, Linux/macOS/Windows CI.
- Single-instance Electron shell, sandboxed isolated renderer, exact sender-frame validation, operation-specific Zod schemas, restricted preload and denied network/navigation/permission access.
- Git utility process with cancellation, time/output limits, a bounded process pool and fair read/write queues.
- Git ≥2.38 locator with optional executable override; repository open/init/discovery; refs/status/history streaming parsers with byte-preserving paths.
- Repository UI with HEAD, branches/remotes/tags and ahead/behind counts, working-tree status, refresh/cancel and a virtualized 2,000-commit list.
- Pure lane allocation, append-only continuation, 500-row checkpoints, worker entrypoint, six golden fixtures and randomized DAG invariants.
- ADRs covering protocol choices, security, scope, graph semantics and validation.

The performance test opens a 2,200-commit fixture through a stubbed native picker, loads 2,000 commits via the real Git utility process, and measures through two animation frames after React's layout commit. The gate is 500 ms. Fewer than 100 history DOM rows are mounted; scrolling reaches the last loaded commit. Results are local-host evidence, not a measurement on a specified mid-range laptop or linux.git.

Parser properties include 400 arbitrary filename/chunk cases, 300 ref cases, 300 history cases, and malformed streams. Graph properties exercise 300 random DAGs with complete parent-path tracing, child-before-parent order, cell uniqueness, lane-frontier bounds, and paging equivalence. Golden fixtures cover linear, merge, octopus, criss-cross, orphan and stash graphs. Real-Git tests also cover unborn/detached HEAD, bare/linked-worktree/submodule/shallow/sparse/SHA-256 repositories, stash bases after branch removal, output limits, timeout, cancellation of a spawned descendant, and writer fairness.

Electron checks confirm `require` and `process` are undefined in the renderer; actual window preferences have sandbox/contextIsolation enabled and nodeIntegration disabled; a normal same-origin script cannot eval under CSP. Packaging verifies RunAsNode, Node options and Node CLI inspection disabled, and embedded ASAR integrity/ASAR-only loading enabled. The smoke check launches that packaged binary with sandboxing intact.

Generated evidence: `test-results/e2e.json`, `test-results/repository.png`, `test-results/packaged-shell.png`. Build output: `release/OpenKraken-linux-x64/`.

## Remaining work

M1 needs the worker-driven Canvas graph, retained Git stream paging, WIP/conflict rows, ref badges, hide/solo/pin, search dimming, keyboard selection and large-repository scrolling benchmarks. M0 intentionally displays a plain list and only the first page. Tabs/settings/URI handling, watchers, staging/commits, credentials and undo are not part of the six explicit tasks in this delivery.

The CI matrix is authored but was not executed remotely. macOS/Windows behavior, Git 2.38 compatibility on an actual binary, signing/installers and platform-specific ASAR integrity enforcement need their respective runners/release validation. No claim is made that this initial milestone implements all 97 parity features.
