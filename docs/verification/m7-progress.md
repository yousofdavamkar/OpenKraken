## Automatic zsh integration

The terminal now supplies bundled zsh startup wrappers that read the user's `.zshenv` and `.zshrc` at top level, preserve inherited or redirected `ZDOTDIR`, and append OSC 133 hooks after user configuration. Named and array hooks, dynamic prompts, command status and pipeline status remain intact in native tests. The wrappers restore the user's final directory setting and do not write user/repository startup files. Disabled prompt-percent expansion, read-only prompt/hook variables and incompatible startup settings retain a normal shell without integration. See [ADR 0109](../decisions/0109-zsh-shell-integration.md), including the limits around custom global startup policies.

The initial native desktop test reproduced absent integration. Fallback tests then caught an attempted write to read-only `ZDOTDIR`; the final wrapper declines that case without a shell diagnostic. Final verification passed **20 terminal Electron tests in 2.0 minutes**, including three zsh startup paths and four fallback configurations, alongside Bash/fish, malformed markers, keyboard isolation, backpressure and lifecycle regressions. **51 IPC/security contract tests**, shell syntax checks, typecheck/build and full ESLint/Prettier passed.

The zsh run verifies the unpacked dotfiles, shell markers, native Ctrl+P delivery, failed-command exit status and clean shutdown; packaged helper/renderer isolation and cold/resident URI consent also passed. Its terminal screenshot was inspected and retained as `test-results/m7-zsh-packaged-terminal.png`. Linux CI installs zsh and repeats a separate packaged zsh smoke. Remote CI was not run.

## Implemented

- A typed command catalogue groups repository, references, history, working-tree, provider, and settings actions by domain. The palette opens with Ctrl/Cmd+P, fuzzy-searches labels and aliases with fuzzysort, filters categories, supports keyboard navigation, and persists bounded frequency/recency weights in main-owned profile settings.
- Commands use existing mounted controls and their enabled conditions. Missing or disabled controls stay discoverable but cannot execute. Dispatch checks availability again and uses existing review dialogs and action handlers. The catalogue does not introduce new Git or provider write paths.
- Palette dismissal restores prior focus; an invoked action owns subsequent focus. Input composition and repeated Enter cannot execute commands. Open dialogs suppress global command shortcuts.
- A JSON keymap editor validates known command IDs, version/schema/size, shortcut syntax, reserved keys, and collisions with inherited defaults on both macOS and Windows/Linux. Explicit null unbinds. Apply persists before activating the map; invalid saved data falls back to defaults and stays available for repair. Restore defaults edits the draft before Apply.
- Native command menus and accelerators use the shared catalogue and saved keymap. Sender-validated context updates mirror availability; modal, revision and typing checks run again before existing actions execute. Native input suppresses repeat/composition, and reload restores context without retaining stale enabled commands.
- Main-owned atomic `settings.json` persistence includes one-time legacy migration, revision-checked keymap saves, serialized usage updates, failed-write retention, and explicit backup repair of damaged settings. Reader and writer byte limits also accommodate maximally escaped legacy keymaps, preserving repair across restart.
- Commit search is part of the catalogue, with overridable Mod+F. Its previous hard-coded global handler is removed. Action shortcuts pause in text editors; opening the palette and focusing commit search remain available outside dialogs.
- Assigned bindings appear in palette rows, button tooltips, and the keymap editor's active shortcut table. No query, repository path, token, arbitrary code, selector, or shell command is stored or executed by the keymap.
- Appearance offers dark, light, system and custom JSON themes through the toolbar and command palette. Main-owned revision-checked persistence shares the atomic profile writer with commands; an appearance-only profile still permits legacy keymap migration. Saved appearance applies before the first application frame and restores the native window preference.
- Shared tokens recolor application surfaces, Canvas lanes, syntax, and CodeMirror views. System changes update open editors in place, retaining drafts, focus and undo history. Toolbar controls wrap within the window. Custom themes inherit a light/dark base and accept only known tokens with CSS hex values; invalid input or failed writes retain the active theme. Electron receives explicit RGBA values to preserve CSS alpha color channel order.
- An on-demand xterm panel starts the user's default shell in the opened repository through a dedicated `node-pty` utility process. Main owns the working directory and accepts only session-scoped, bounded input, sizing and acknowledgment messages. Output backpressure pauses the PTY until rendering catches up. Hiding preserves the session; F6 reaches controls; the toolbar restores focus. Closing a live session requires confirmation, and reload/window closure ends the utility. A missing shell reports a recoverable error. Renderer isolation and the existing Git service remain in place.
- OSC 133 markers show prompt, command-running and reported exit-code state without granting any authority to shell output. Bash 5.1+ receives a bundled rcfile that first sources the user's `.bashrc` and preserves scalar/array prompt hooks, PS0, dynamic PS1, DEBUG traps, `$?` and PIPESTATUS. Older Bash or incompatible prompt settings keep the normal terminal. Fish's native parameterized markers are accepted with explicit opt-out preserved. Zsh receives bundled startup wrappers and appended prompt/preexec hooks, with native Linux and packaged acceptance. Automatic PowerShell integration remains open.
- Worktrees are listed with main/current, branch/detached, commit, dirty-file, lock and missing-folder state. A registered checkout can be opened by a validated ID and inventory revision. Creation supports a new branch, an unused existing local branch or detached HEAD at an explicit commit, with an empty destination chosen through the native folder picker. Shared-repository writes use the existing queue and watcher suppression. Creation keeps the current checkout unchanged; cancellation/errors retain form choices. Newline-containing repository metadata uses an unambiguous fallback read.
- Reviewed lock/unlock actions support offline worktrees and bounded lock reasons. Removal retains branches, refuses main/current/locked or unavailable checkouts, and checks ignored/untracked/modified files, index flags that can conceal edits, ongoing Git operations and unreferenced detached commits. Reviews remain open on failure; cancellation and success restore focus, and removal review initially focuses Cancel.

- Worktree cleanup shows Git’s bounded dry-run report before pruning stale registrations. Repository-bound, expiring tokens and a fixed cutoff bind confirmation to the reviewed inventory and metadata fingerprint. Confirmation rechecks detached HEAD retention and consumes the token before execution. Locked/live checkouts and branches remain; the UI explains that registration index/reflog recovery data is removed.

- Worktree HEADs seed history and search, including detached checkout-only commits, while respecting hidden/solo ref filters. Each other non-bare checkout has a stable synthetic graph row above its HEAD, with status, branch and path, loaded search, details and ancestry navigation. Rows are inserted on the parent’s page without moving earlier lanes. Other-checkout status is updated automatically through native subscriptions and a typed status-only event, preserving loaded pages, selection, search and row details. New registrations become watched; unavailable checkouts are polled for reconnection. Changed HEADs or inventory use a full refresh.

- Submodules are discovered recursively from index gitlinks, with configured URLs, recorded/checked-out commits, status and initialization state. The toolbar/command dialog opens a reviewed initialized checkout and supports refresh after stale selections. Paths are selected by service-issued identities; symlinks, ambiguous configuration, ancestor cycles and discovery bounds are checked. Reviewed recursive initialization/update is covered below.

- History pages use a typed JSON response format, serialized in main after validation, to avoid copying thousands of nested objects through renderer IPC and the isolated-world bridge. Existing request validation, cancellation, cursor checks, append-only layout and performance budgets remain in place.

- Reviewed recursive submodule initialization/update uses service-owned expiring tokens, exact recorded commits and literal top-level paths. Preflight protects active and dormant local work; local-file transport requires an explicit opt-in, TLS verification stays enabled, and external-helper rewrites are blocked. The dialog exposes source review, progress, cancellation and partial-completion messaging. Existing askpass support is connected, but live authenticated-provider acceptance remains open.

- The Git LFS toolbar/palette view detects the installed CLI and shows native tracked-file identities, sizes, checkout flags, local object availability and cached lock owners without downloading objects or refreshing the server. Cached ownership is explicitly not current server state. Commit and working-file comparisons recognize canonical pointer metadata without requiring Git LFS, preserving 64-bit sizes. Native LFS acceptance is required in CI; the local tests use an isolated, checksum-verified Git LFS 3.8.1 binary.

- Reviewed HTTP(S) LFS downloads show the configured remote endpoint, filters and known file identities before confirmation. Service-owned expiring tokens bind execution to repository/configuration state and are consumed before native pull. Progress and cancellation use the existing Git service; failures explain possible partial changes. Native checkout retains edited files, configured exclusions remain effective, TLS verification is enforced and corrupt objects are rejected. Repository toolbar controls now have distinct React keys, preventing duplicated controls and a retained parent dialog when opening another checkout.

- Ordinary Pull carries the active native authentication session into merge/rebase checkout, allowing installed Git LFS filters to download incoming objects. Saved-account integration retains the protected transport configuration used during fetch, preventing fallback to repository credential stores for a different LFS host. Integration certificate failures use the existing transport classification. Native filters and skip-smudge preferences remain user-configured.

- Explicit server-lock refresh queries the selected HTTP(S) LFS endpoint with native authentication/cancellation and shows its remote, endpoint and check time. Tracked rows distinguish reported ownership from cached state. Failed queries and remote/local refresh changes clear the server snapshot. Successful refresh updates the native and visible caches. The service detects query failures before consuming cached JSON, avoiding the CLI's JSON mode hiding failed server reads as empty results.

- Ordinary reviewed Push is verified with an installed native LFS pre-push hook. Native credentials and cancellation reach the upload, unrelated branch objects remain local, and rejected/missing/canceled/untrusted transfers prevent ref publication in Linux fixtures. Desktop acceptance covers successful authenticated uploads, server rejection, cancellation and fresh review/retry. This is acceptance of the existing Push path; no production transport behavior changed.

- Reviewed local LFS setup shows the chosen checkout mode, filter scope/file and resolved hook directory. It uses native local/worktree installation without force, rehearses filters and hooks in an isolated temporary repository, and preserves custom integrations. Repository-bound tokens reject stale inputs; effective filters are verified after installation. The dialog supports cancellation, partial-change messaging and deliberate focus restoration.

- Reviewed recursive submodule URL synchronization replaces registered local URLs from `.gitmodules` through native Git resolution. Expiring single-use reviews bind inventory, branch context and configuration. The dialog shows existing overrides, explains shared configuration and partial failure, restores focus and supports fresh review/retry. Dirty files, staged content and checked-out commits are retained without network access.

- A local activity history records admitted foreground Git/provider operations and selected settings changes with fixed action names, times and outcomes. It persists up to 500 entries outside repositories, excludes payloads and credentials, marks interrupted outcomes unknown, and retains running entries when completed history is cleared. The toolbar/palette/native-menu view filters and pages entries, restores focus and reports storage failures without hiding operation results. A separate shutdown fix defers final quit after cleanup when the Git utility has already exited.

## Remaining M7 scope

- Broader command coverage, including dynamic branch/file domains and contextual commands. Native accelerators are implemented; this is not an Atom selector keymap interpreter. Other older preferences (for example graph view settings) still need consolidation into the main settings store.
- Automatic shell integration for PowerShell, plus terminal runtime acceptance on macOS/Windows. Standard OSC 133 consumption, automatic Bash 5.1+/zsh integration and fish native prompt-marker support are implemented. Zsh 5.9 and fish 4.2.1 have Linux acceptance; custom global zsh startup policies, older fish versions and third-party prompt integrations need further runtime coverage. The initial terminal supports one session; broader terminal workflows remain future work.
- Worktree operations, graph rows and other-checkout observation are implemented for UTF-8 paths on Linux. Non-UTF-8 worktree paths, cross-platform runtime acceptance and broader filesystem/performance coverage remain open. Submodule discovery/status/opening, reviewed recursive initialization/update and URL synchronization are implemented. Add/remove controls, automatic dialog refresh, live authenticated transport acceptance and cross-platform runtime verification remain open. Local LFS awareness, cached-lock display, explicit server-lock snapshots and reviewed HTTP(S) LFS pulls are implemented. Ordinary Pull with installed native filters and reviewed Push with an installed pre-push hook have authenticated Linux fixture coverage. Reviewed local/worktree setup is implemented with custom integrations preserved for manual resolution. Reviewed SSH/file/custom transfers, saved-account LFS upload acceptance, fresh filter authentication during other operations, live-provider acceptance and packaged/cross-platform LFS verification remain open. Lock acquisition/release is not implemented; the server snapshot reports ownership at its displayed check time.
- Onboarding, toasts, a complete accessibility pass, and i18n scaffolding. Local operation activity is implemented; it is not a durable write-recovery journal or an audit of external changes.
- Optional git-flow and consent-gated BYO-key AI remain optional, not implemented.

Cross-platform keyboard execution and packaging remain unverified on macOS/Windows. M8 release requirements (signed updates/installers, opt-in crash reporting, security review, beta evidence, and broader regression gates) remain open. Native command supervision has Linux crash-fixture coverage; cross-platform runtime acceptance and broader write recovery remain open. Existing Linux security/package checks do not establish release completion.
