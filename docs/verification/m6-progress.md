# M6 progress — provider integrations

M6 is in progress as of 2026-11-02, at implementation checkpoint `51e8776`. M0–M5 retain their documented Linux acceptance scope; M6–M8 remain open. React 19.3.1 and TypeScript 7.0.2 remain pinned.

## Implemented

- A main-process provider boundary and Octokit GitHub/GHES account validation using HTTPS-only configured origins, cookie-free requests, redirect refusal, cancellation, timeouts and bounded response bodies.
- OS-protected credential storage through asynchronous Electron safeStorage, refusal of Linux plaintext/unknown backends, encrypted account-bound envelopes, serialized atomic writes and key rotation.
- A desktop account dialog with token validation, metadata-only responses, offline account listing, reconnection after login changes, local forgetting and cancellation when setup closes.
- Strict IPC schemas keep saved provider credentials out of renderer requests and responses and reject malformed origins without leaking raw URL exceptions. Tokens are cleared from the password field before requests; provider error bodies and request diagnostics are not shown.
- GitHub device authorization with a configured client ID, explicit private-repository scope, fixed browser destination, main-enforced polling/slow-down/expiry and cancellation. Private device codes remain in main.
- Protected access/refresh-token storage, identity validation after sign-in, and a Verify action that refreshes expiring device credentials while checking the original account identity.
- GitHub/GHES repository pages with identity validation and protected refresh, canonical HTTPS clone URLs, bounded metadata and explicit paging limits.
- A provider repository picker in Clone with virtualized rows, loaded-result search, append/deduplication, keyboard selection, account switching, cancellation and retry. Selection feeds the existing native clone flow.
- Saved-account HTTPS cloning through a URL-bound native askpass scope, with no renderer prompts, plaintext helper store, token environment variables or token command arguments. Per-operation safeguards refuse rewrites and redirects, retain TLS verification and disable trace output.
- Foreground HTTPS fetch with a saved account selected in Manage remotes. Main checks the displayed remote revision before credential access; the Git service rechecks URL/configuration under its repository queue. Stale, changed and cancelled attempts do not contact the Git server.
- Saved-account HTTPS push review and execution using the configured push URL. Account selection locks after review; local-source/configuration guards, non-fast-forward rejection and exact force-with-lease remain enforced. Review again reloads remote metadata.
- Saved-account HTTPS pull with local-only upstream/URL/policy review, separate working-state and remote revision checks, refusal after configuration changes during account validation, and retained integration/Undo behavior.
- Saved-account remote branch/tag deletion with push-direction resolution, a locked account/ref review, separate confirmation and exact server-tip leases. Closing a review preserves server refs; rejected leases require re-review. Local branches and tags remain intact.
- Repository-scoped GitHub/GHES PR lists and details with protected account validation, strict selectors, bounded paging/metadata, canonical display URLs and sanitized failures.
- A desktop PR panel with repository selection, virtualized append/deduplication, state filters, loaded-result search, keyboard navigation, detail retry/refresh and cancellation on repository changes or close. Descriptions render as text.
- Revision-checked GitHub/GHES changed-file pages with rename metadata, bounded/missing provider patches, virtualized keyboard selection and read-only CodeMirror display.
- Paged review records and an explicit preview/submit composer for comments, approvals and requests for changes. Main checks displayed head/base and PR state, binds the reviewed head, and never retries an uncertain write automatically. Draft text survives errors and review inspection is available after uncertainty.
- Inline comment pages grouped into virtualized discussions, with literal text, original/outdated locations and expandable diff context. New single-line comments map patch coordinates to the reviewed commit; replies validate the original thread and selected PR before sending. Both use preview/confirmation, retain unsent text on failures and never automatically retry uncertain writes.
- Provider-direct PR creation from pushed same-repository or fork branches, with reviewed head/base commits, explicit draft/maintainer-edit flags, confirmation, stale-tip refusal and uncertain-result inspection without automatic retries.
- Pinned default-branch repository templates discovered through bounded Git-tree traversal, regular-file checks and strict UTF-8/blob validation. Template preview requires a separate action to replace the description.
- Direct PR merge with fresh repository policy/permission metadata, supported method selection, optional merge/squash messages, explicit confirmation, reviewed head/base/ref guards and the provider head-SHA condition. Rejections require a refreshed preview; uncertain outcomes can be checked without retrying writes.
- GitHub/GHES PR check rollups through a fixed GraphQL query, bound to the displayed head, with check-run and legacy-status paging, strict partial-error refusal, manual refresh and a virtualized 1,000-context display limit.
- GitHub/GHES issue lists, details and comment pages, including PR exclusion with raw-page continuation, bounded metadata, canonical display URLs, loaded-result search, keyboard selection, virtualized comments, refresh/retry and cancellation.
- Reviewed issue creation, comment submission and close/reopen with exact payloads, fresh snapshot guards, separate confirmation, preserved drafts, one-write handling and read-only uncertain-result inspection.
- Conditional GitHub/GHES GETs with a private, bounded memory cache, server revalidation, credential/host/page/filter isolation, expiry, storage-policy enforcement and invalidation after writes or account changes. Errors never substitute stale cached data.
- Main-enforced server cooldowns, fallback exponential delays, provider polling-interval metadata and typed retry timestamps. Known preflight quota exhaustion stops writes before dispatch; uncertain outcomes remain distinct. Timing-policy lookup does not make network requests or expose credentials.
- Opt-in scheduled refresh for issue and PR lists, selected details and every loaded comment/file/review/check page, with persisted intervals, provider timing, complete-batch updates, preserved search/selection/expanded discussions, commit-context guards, draft pause and cancellation on input, window inactivity or context changes.
- Provider/vault queues retain only completion, avoiding retention of the last decrypted credential value.
- Shutdown cancels provider validation and waits for pending profile work alongside the Git service, retaining the existing deadline and editor Quit-cancellation behavior.

## Remaining

GitLab PKCE and its provider adapter come next, followed by the other planned providers. Scheduled GitHub/GHES polling is implemented; timing remains session-local and live-provider acceptance remains outstanding. Repository fork/create and SSH key upload remain open. Direct selected-PR merges are implemented; asynchronous merge queues/stacks require a separate reviewed workflow. Provider patches, whole-PR submitted reviews, inline discussions, single-line comments and replies are implemented; thread resolution, comment editing/deletion and multi-line/file-level comment creation are not included in these slices; durable issue and PR drafts and recovery of external writes across app quit/reload/crash remain hardening work. GitLab PKCE and provider fixture coverage are still required; optional Jira is lower priority. Account/organization fallback templates and automatic branch suggestions are not included in the creation slice. No server component is planned. A device flow requires a configured OAuth application client ID, not an invented or borrowed registration.

Account sign-in, repository picking and saved-account HTTPS clone, foreground fetch, reviewed push/pull, remote deletion, PR browsing/files, submitted reviews, inline discussions, creation with repository templates, direct merge, check displays, issue browsing, reviewed issue actions, conditional reads, provider timing policy and scheduled refresh are implemented slices, not completion of M6. A user-supplied OAuth application client ID is required for live device authorization; no registration was invented or borrowed. Refreshing uses the stored client ID and protected refresh token. A server-side rotation followed by a failed local write can require signing in again. Existing Git credential helpers and SSH agents continue to handle manual clone/fetch/push; provider-selected HTTPS clones, foreground fetches, reviewed pushes/pulls and remote deletions can use their protected account credential. Automatic fetch retains its existing noninteractive helper flow. Authenticated lazy fetching during partial-clone working-tree operations needs acceptance coverage. Cross-file credential/metadata crash recovery, real-keychain and cross-platform runtime acceptance remain further work.
